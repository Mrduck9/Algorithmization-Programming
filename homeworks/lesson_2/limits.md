# Выбор решения под ограничения · занятие 3

## Задание

### 1. Список номеров заказов за сутки, `n ≤ 200 000`. Найти, есть ли среди них хотя бы два одинаковых.
**1. Какой класс сложности проходит.**
   O(n) = 200 000 операций и есть.
**2. Предполагаемое решение.**
   Создать множество на основе списка (оставит все номера в единичном экземпляре). Далее один раз пройти по списку, проверяя, есть ли такой номер в множестве: если нет - добавляем в множество, если да - мы нашли повтор, вернуть True. 
   По времени: O(n), т.к проходим по списку 1 раз;
   По памяти: O(n), т.к создаём множество - новую структуру данных.
**3. Что мешает взять решение проще.**
   Попарное сравнение всех чисел с помощью вложенного цикла - O(n^2) по времени, кол-во операций - 200 000^2 = 4·10^10 операций, что сильно больше ограничения в 10^7.
### 2. Список цен на складе, `n ≤ 100 000`. Найти три самые дешёвые позиции.
**1. Какой класс сложности проходит.**
   О(n log n) = 1 660 964 < 10^7.
**2. Предполагаемое решение.**
   Отсортировать список и взять первые три.
   По времени: O(n log n), т.к нужно провести сортировку;
   По памяти: O(1), т.к не создаём новых структур.
**3. Что мешает взять решение проще.**
   Переход всех троек - O(n³): 100 000^3 = 10^15.
### 3. Отсортированный архив чеков, `n ≤ 10⁷`, запросов `q ≤ 10⁵`. По каждому запросу сказать, есть ли такой чек.
**1. Какой класс сложности проходит.**
   O(q log n) = 2325350 < 10^7.
**2. Предполагаемое решение.**
   Архив отсортирова - можно на каждый запрос q искать чек с помощью бинарного поиска (log n).
   По времени: O(q log n), т.к проходим по одному списку и паралельно проводим бинарный поиск во втором;
   По памяти: O(1), т.к не создаём новых структур.
**3. Что мешает взять решение проще.**
   Линейный поиск по обоим спискам - q*n - 10⁷ * 10⁵ = 10^12 - не укладывается в лимит.
### 4. Координаты курьеров, `n ≤ 3 000`. Найти два ближайших друг к другу.
**1. Какой класс сложности проходит.**
   O(n²) = 9*10^6 < 10^7.
**2. Предполагаемое решение.**
   Двойной цикл по всем парам, где нужно считать расстояние между для каждой.
   По времени: O(n²), т.к проходим по каждой возможной паре в списке;
   По памяти: O(1), т.к не создаём новых структур.   
**3. Что мешает взять решение проще.**
   Это и есть самое простое решение: при лимите входных данных в 3 000 сложность n^2 подходит - 3 000^2 = 9*10^6.
### 5. Одно число `k ≤ 10⁹`. Сказать, сколько раз его можно разделить пополам до единицы.
**1. Какой класс сложности проходит.**
   O(log k) = 30 < 10^7.
**2. Предполагаемое решение.**
   Делить число на 2, пока оно не станет меньше единицы.
   По времени: O(log k), т.к делим число пополам;
   По памяти: O(1), т.к не создаём новых структур.  
**3. Что мешает взять решение проще.**
   Для одного числа решения проще не бывает.
### 6. Два списка накладных, `n ≤ 10⁵` и `m ≤ 10⁵`, оба отсортированы. Собрать из них один отсортированный список.
**1. Какой класс сложности проходит.**
   O(n + m) = 2*10^5 < 10^7.
**2. Предполагаемое решение.**
   Одновременно пройтись по обоим спискам, выбирать меньшее число и заносить его в новый список, сдвигать указатель.
   По времени: O(n + m), т.к проходимся по обоим спискам;
   По памяти: O(n + m), создаётся новый список, содержащий два предыдущих.  
**3. Что мешает взять решение проще.**
   Просто склеить списки и отсортировать - O((n + m) log(n + m)) = миллион операций: можно взять, но в данном случае доп.сортировка после склеивания является лишней операцией, когда мы модем сэкономить время.
