# Выбор решения под ограничения · занятие 3

## Задание

### 1. Список номеров заказов за сутки, `n ≤ 200 000`. Найти, есть ли среди них хотя бы два одинаковых.
**1. Какой класс сложности проходит.**
   O(n) = 200 000 операций, что укладывается в лимит.
**2. Предполагаемое решение.**
   Создать множество из списка (оно оставит только уникальные номера). Затем один раз пройти по списку, проверяя наличие номера в множестве: если его нет — добавляем, если есть — нашли дубликат, возвращаем True. 
   По времени: O(n), так как список проходится один раз;
   По памяти: O(n), так как создаётся новая структура данных — множество.
**3. Что мешает взять решение проще.**
   Сравнение всех пар чисел через вложенный цикл даст O(n^2) по времени, что составит 200 000^2 = 4·10^10 операций — значительно больше допустимых 10^7.

### 2. Список цен на складе, `n ≤ 100 000`. Найти три самые дешёвые позиции.
**1. Какой класс сложности проходит.**
   О(n log n) = 1 660 964 < 10^7.
**2. Предполагаемое решение.**
   Отсортировать список и взять первые три элемента.
   По времени: O(n log n), так как требуется сортировка;
   По памяти: O(1), новые структуры не создаются.
**3. Что мешает взять решение проще.**
   Перебор всех возможных троек — O(n³): 100 000^3 = 10^15, что недопустимо.

### 3. Отсортированный архив чеков, `n ≤ 10⁷`, запросов `q ≤ 10⁵`. По каждому запросу сказать, есть ли такой чек.
**1. Какой класс сложности проходит.**
   O(q log n) = 2325350 < 10^7.
**2. Предполагаемое решение.**
   Архив уже отсортирован, поэтому для каждого запроса q можно использовать бинарный поиск (log n).
   По времени: O(q log n), так как обрабатываем запросы и выполняем бинарный поиск;
   По памяти: O(1), новые структуры не создаются.
**3. Что мешает взять решение проще.**
   Линейный поиск по обоим спискам — q*n — 10⁷ * 10⁵ = 10^12, что выходит за рамки лимита.

### 4. Координаты курьеров, `n ≤ 3 000`. Найти два ближайших друг к другу.
**1. Какой класс сложности проходит.**
   O(n²) = 9*10^6 < 10^7.
**2. Предполагаемое решение.**
   Двойной цикл по всем парам с вычислением расстояния для каждой.
   По времени: O(n²), так как перебираются все возможные пары;
   По памяти: O(1), новые структуры не создаются.   
**3. Что мешает взять решение проще.**
   Это и есть самое простое решение: при лимите в 3 000 элементов сложность n^2 подходит — 3 000^2 = 9*10^6.

### 5. Одно число `k ≤ 10⁹`. Сказать, сколько раз его можно разделить пополам до единицы.
**1. Какой класс сложности проходит.**
   O(log k) = 30 < 10^7.
**2. Предполагаемое решение.**
   Делить число на 2 до тех пор, пока оно не станет меньше единицы.
   По времени: O(log k), так как число уменьшается вдвое на каждом шаге;
   По памяти: O(1), новые структуры не создаются.  
**3. Что мешает взять решение проще.**
   Для одного числа более простого решения не существует.

### 6. Два списка накладных, `n ≤ 10⁵` и `m ≤ 10⁵`, оба отсортированы. Собрать из них один отсортированный список.
**1. Какой класс сложности проходит.**
   O(n + m) = 2*10^5 < 10^7.
**2. Предполагаемое решение.**
   Одновременно проходить по обоим спискам, выбирать меньшее число и добавлять его в новый список, сдвигая указатель.
   По времени: O(n + m), так как проходим по обоим спискам;
   По памяти: O(n + m), создаётся новый объединённый список.  
**3. Что мешает взять решение проще.**
   Склеить списки и отсортировать — O((n + m) log(n + m)) — около миллиона операций. Это допустимо, но дополнительная сортировка после склейки избыточна, когда можно сэкономить время.
